# 求职展示与面试讲解

## 项目描述参考

> InstrumentLab 智能仪器采集与分析平台：使用 Python 构建桌面测量工作站，实现仿真仪器与 TCP 仪器驱动、连续数据采集、FFT 频谱分析、线性标定、带回差的过载告警，以及 SQLite 录制和 CSV 导出。通过算法与 TCP 回环集成测试验证数值计算、异常连接、数据持久化和采集生命周期。

技术关键词：Python、Tkinter、TCP Socket、多线程、生产者/消费者、FFT、数字信号处理、SQLite、单元测试、GitHub Actions。

## 推荐讲解顺序

1. **问题**：测量软件需要把仪器通信、分析、可视化和数据追溯串起来，而界面不能被网络等待阻塞。
2. **演示**：先说明数据是仿真源，启动周期过载，展示波形、主频、ALARM 与 RECOVERED 事件。
3. **设计**：驱动可替换，工作线程独占 Socket 与数据库；GUI 只从队列更新控件。
4. **准确性**：解释 RMS 含直流分量、Hann 窗与幅度校正，以及主频插值的物理限制。
5. **验证**：展示测试输出、TCP 独立进程演示、原始和校正数据导出。
6. **边界**：目前单通道、协议为自定义子集，尚未实机验证；提出接入具体仪器的下一步方案。

## 常见追问

**为什么不在按钮回调里直接读仪器？**

TCP 连接或读取可能等待到超时，如果在 Tk 主线程执行，窗口会失去响应。这里把通信和数据处理放在工作线程，通过队列传递结果，停止使用 Event，并在 finally 中清理连接与数据库。

**界面显示丢帧意味着采样数据丢失吗？**

本项目中数据先写 SQLite，再进入 8 帧显示队列。显示积压可以丢旧帧，已成功保存的数据仍在数据库。但这不证明硬件端不丢样：当前协议没有设备块序号、设备时间戳或缓冲区溢出标志。

**为什么 50 Hz 信号在频谱上不是一根针？**

默认 1024 Hz / 256 点，对应 4 Hz 频率间隔，50 Hz 不在整数频点。非整周期截断导致泄漏，Hann 窗降低旁瓣但会展宽主瓣。幅度谱做相干增益校正，但非整频点仍可能有栅栏效应。

**50.0 Hz 的显示是否意味着 0.1 Hz 分辨率？**

不意味着。显示是对频谱峰做插值后的估计，FFT 频率间隔仍为 4 Hz；要分开距离很近的两个频率，通常需要更长的观测时长。

**为什么要回差和连续帧确认？**

回差把触发与恢复阈值分开，连续帧确认过滤单帧尖峰。代价是检测延迟；应该根据设备保护需求设计，不能把本项目的软件演示当安全联锁。

**标定残差小就代表设备精度高吗？**

不代表。残差只是所给点上的拟合误差；还要考虑标准源不确定度、重复性、温漂、量化噪声以及量程外行为。本项目没有计量溯源或实机精度报告。

**“智能分析”具体是什么？**

峰值阈值状态机，以及块均值和峰值因数规则。没有使用机器学习，不能报告模型准确率。加入模型前需要带标签的实测数据和独立评估集。
